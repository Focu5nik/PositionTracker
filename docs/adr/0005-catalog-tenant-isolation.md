# ADR-0005. Изоляция каталога филиалов

**Статус** — принято в v0.2.

Владелец филиала определяется по цепочке `Location → Company → Tenant`. `Membership` связывает пользователя с tenant. Ограничение БД допускает одну запись на пару `(user, tenant)`. Роли `owner` и `viewer` дают одинаковый доступ на чтение. Уникальность идентификатора синтетической карточки ограничена одной компанией, чтобы разные компании могли ссылаться на одну карточку.

Пользователь может указать чужой ID филиала или компании и передать `tenant_id` в заголовке или query string. Два маршрута DRF используют общий queryset, который ограничивает выборку по актуальным `Membership` аутентифицированного пользователя. ID компании или филиала сужает уже ограниченную выборку. Чужой и отсутствующий филиалы дают `404`. Для чужой, отсутствующей или пустой компании список одинаково возвращает `200` и `[]`.

Отдельная проверка прав после загрузки объекта потребовала бы отдельной фильтрации списка. Общий queryset применяет политику до чтения данных в каждом из двух маршрутов. Граница действует в API монолита. Для новых маршрутов чтения каталога потребуется такая же привязка к членству.

Каталог получает пользователя из сессии Django. Протокол входа и граница доступа админки описаны в [ADR-0006](0006-session-auth-and-admin.md).
