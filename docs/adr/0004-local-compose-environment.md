# ADR-0004. Общая локальная сборка и изоляция баз

**Статус** — принято в v0.1.

Для локальной среды используем один Python-образ и один `uv.lock`. Compose запускает образ с разными командами для Django и FastAPI. Альтернатива — отдельные образы и lock-файлы. Это позволит обновлять приложения независимо, но увеличит число сборок и конфигураций для проверки. Общий образ предназначен для локальной разработки и CI.

Один экземпляр PostgreSQL обслуживает две логические базы. Каждая принадлежит своей прикладной роли и закрыта для `PUBLIC`. Приложение получает пароль своей роли. При инициализации PostgreSQL использует обе пары, но отдельно от приложений. Два экземпляра PostgreSQL также изолировали бы ресурсы и сбои на уровне процессов, а в локальном окружении увеличили бы число контейнеров.

`/health/live` проверяет работу HTTP-процесса, `/health/ready` — запрос с учётными данными приложения. RabbitMQ запускается для проверки окружения. Доступность брокера будет иметь значение для обработчиков очереди, когда они появятся.

Имена прикладных баз и ролей задаются в `.env`, шаблон значений хранится в `.env.example`. Compose передаёт параметры в PostgreSQL и в соответствующее приложение. SQL читает их через `\getenv` и экранирует как идентификаторы с помощью `:"variable"`. Альтернатива — фиксированные имена в SQL и Compose — требует синхронного редактирования двух файлов при переименовании. Тест получает имя чужой базы через `TEST_OTHER_DB_NAME`, а подключается к ней с правами своей роли.
