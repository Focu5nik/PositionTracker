# ADR-0003. Celery и RabbitMQ для доставки команд

**Статус** — принято в v0.0.

Запуск возвращает управление пользователю, пока отдельные исполнители обрабатывают проверки. Планировщик сохраняет задания в PostgreSQL. Dispatcher публикует команды с `check_id`, RabbitMQ доставляет их Celery worker. Команда просит выполнить конкретную проверку. Будущее событие о позиции будет описывать уже записанный факт.

PostgreSQL хранит задания, попытки и результаты. Worker читает параметры из БД и выполняет вызов провайдера между транзакциями захвата задания и записи результата. Наблюдение и переход в `SUCCEEDED` сохраняются атомарно. После COMMIT worker подтверждает сообщение. Повторная доставка допускается, поэтому терминальное состояние и уникальность наблюдения по `check_id` защищают результат. Dispatcher должен восстанавливать публикацию при сбое между подтверждением брокера и обновлением состояния задания.

Альтернатива — workers опрашивают PostgreSQL напрямую. У неё меньше инфраструктуры и отсутствует граница между записью задания и публикацией. Celery с RabbitMQ дают отдельную доставку команд и позволяют отработать подтверждения, повторы и восстановление после падений. Эта схема требует проверки повторной доставки и согласования состояния задания с брокером.
