# История изменений

## v0.2 — Каталог филиалов

- Добавлены модели `Tenant`, `Company`, `Location` и `Membership` с ограничениями БД.
- Добавлены два маршрута чтения филиалов с сессионной аутентификацией и фильтрацией по членству пользователя в tenant.
- Добавлены вход и выход с CSRF-защитой, Django Admin для каталога и команда `seed_demo` с двумя пользователями и двумя филиалами.
- Для списка и карточки филиала подключён DRF Browsable API с формами входа и выхода.
- Добавлены тесты изоляции списка и карточки, границ координат и уникальности записей.

## v0.1 — Локальное окружение

- Имена прикладных баз и ролей вынесены в переменные окружения для SQL, Compose и проверок изоляции.
- Добавлены Compose для Django, FastAPI, PostgreSQL и RabbitMQ и общий Python-образ с зафиксированными зависимостями.
- Для Django и FastAPI настроены разные базы и роли PostgreSQL. Добавлены проверки liveness и readiness.
- Добавлены команды запуска, миграций и тестов, а также GitHub Actions для lint, type checking, тестов и проверки Compose.

## v0.0 — Продуктовый контракт

- Описан ручной запуск Coffee Demo из 150 проверок для трёх филиалов, двух запросов, одной синтетической платформы и сетки 5×5.
- Заданы четыре outcome, формулы отчёта и критерии приёмки, включая повтор запроса и восстановление после сбоя.
- Зафиксированы архитектурные решения о двух владельцах данных, отчётности PostgreSQL и доставке команд Celery/RabbitMQ.
- Добавлены 10 эталонных выдач, шаблон для остальных 140 проверок и точные ожидаемые метрики для обеих выборок.
